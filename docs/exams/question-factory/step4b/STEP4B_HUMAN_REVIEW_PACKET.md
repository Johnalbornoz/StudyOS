**Minimum successful reasoning path** (proposed wording)

3. Where one root is asked for, compare the two roots and give the one asked for.

| Reasoning | Value |
|---|---|
| SUPPORTED_REASONING_STRATEGIES | FACTORISING, QUADRATIC_FORMULA, COMPLETING_THE_SQUARE, INSPECTION |

| Construct necessity (the claim to check) | The keyed value is a root of the equation and the stem offers no candidate value, so a correct response is reached only by solving the equation. Which method was used is not claimed. |

**Solution invariants**
- Relationship: a * (x - r1) * (x - r2) = 0
- Relationship: b = -a * (r1 + r2)
- Relationship: c = a * r1 * r2
- Constraint: b and c are integers.
- Constraint: The equation is built from its roots, never the roots from arbitrary coefficients.
- Constraint: The two roots are different and neither is zero.
- Solution rule: Both roots are rational: an integer or a half.
- Solution rule: When one root is asked, the stem says which one, so the response has one value.
- Solution rule: No method is required: factorising, the quadratic formula, completing the square and inspection all reach the keyed roots.

**Solution invariants**

- Relationship: x = b * c / a
- Constraint: c is not equal to a.
- Constraint: a, b and c are positive.

### Item structure and response representation are two dimensions

MULTI_PART says how an item is **structured** (several marked parts). MATH_EXPRESSION, SHORT_RESPONSE and EXTENDED_RESPONSE say how a response is **represented**. They do not compete: a multi-part item may have a part answered by a mathematical expression. This adapter admits the structures SINGLE_PART and MULTI_PART and the representations MATH_EXPRESSION, SHORT_RESPONSE, EXTENDED_RESPONSE.

The historical generation profile `IB.MATH_AA.HL.P1` lists MULTI_PART among its "formats". That is a structure code; it is read here as structure, which the adapter admits. Nothing is chosen between the two, and the adapter is not changed.
The adapter also governs MATH_EXPRESSION that the generation profile never asks for. A generator using less than the assessment model allows is not a defect of the model.

To note when deciding: the multi-part structure rests on `ib.marks = MULTI_MARK_PARTS`, a PROVISIONAL line of the table above (StudyUs's reading of the two recorded sections). Approving the adapter confirms it.
