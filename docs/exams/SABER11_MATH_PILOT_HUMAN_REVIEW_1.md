## 2. Human review methodology

**Reviewer**
- A Colombian mathematics teacher familiar with Saber 11 / Icfes, ideally not the author, with experience in multiple-choice items and Saber 11 competences.
- Identity is the existing model: `question_bank_reviews.reviewed_by` points to `users.id`, taken from the reviewer's own authenticated admin session. No other personal data is stored.
- The system never infers the reviewer: no CLI or script records decisions.
- The factory identity (the author) is refused with `SELF_REVIEW`.

**Package.** [`question-bank/pilots/saber11-math/HUMAN_REVIEW_BATCH_1_PACKAGE.md`](question-bank/pilots/saber11-math/HUMAN_REVIEW_BATCH_1_PACKAGE.md), generated by `review-package` (read-only). It has one card per item:
- identity and batch;
- stimulus, stem, options, proposed key, worked solution and generator distractor rationales;
- proposed competence, assertion, evidence (the generator's claim), content category, StudyUs difficulty, locale, marks and type;
- the Blueprint cell, requested vs proposed vs V2.1;
- automated validation: outcome, recomputed key, findings, independent validator signal, explicitly *not* an approval;
- the attention points;
- the checklist.

**Where decisions are recorded.** Admin → Banco de preguntas → Revisión → item. Same 9-point contract, no second checklist.

| Checklist key | Meaning |
|---|---|
| `ANSWER` | Key correct and the only defensible answer |
| `DISTRACTORS` | Plausible and clearly incorrect |
| `COMPETENCE` | Assesses the indicated competence |
| `ASSERTION_EVIDENCE` | Matches the Icfes assertion / evidence |
| `CONTENT_CATEGORY` | Matches the indicated content category |
| `DIFFICULTY` | StudyUs difficulty correct |
| `LANGUAGE` | Clear es-CO |
| `SOLUTION` | Solution correct and complete |
| `ORIGINALITY` | Not a reproduction / paraphrase of released Icfes items |

**What every decision must contain** (enforced by the UI, the service and the DB)

| Decision (brief / DB) | Required |
|---|---|
| any | All 9 points answered explicitly, Sí or No. "Not answered" is never stored as "failed". The reviewer's own competence, content category, StudyUs difficulty and correct option (or "none / more than one"). An answer (confirm / not confirm) to every attention point. |
| `HUMAN_APPROVED` / `APPROVED` | All 9 points Sí. Each confirmed point must agree with what the reviewer determined (e.g. `ANSWER` = Sí requires reviewed option = key). Validated difficulty = the reviewer's StudyUs difficulty, never a pre-filled default. |
| `CORRECTION_REQUIRED` / `CORRECTION_REQUESTED` | At least one No, a comment, and correction notes. The item goes to `REVIEW_REQUIRED`, which is not delivered and does not count for readiness. |
| `REJECTED` | At least one No and the reason. The item goes to `REJECTED`. It returns only as a new version through the existing correction workflow, followed by a new review. |

- `20261101_1000` refused APPROVED with a **failed** point. That is confirmed.
- It did **not** refuse an **unconfirmed** (absent) point, a correction or rejection naming no failure, or a pilot review without the reviewer's classification.
