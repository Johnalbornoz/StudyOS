# LX-9 AI Runtime Performance Audit

Complete inventory of every runtime `executeAI(...)` call site in the codebase, as of this phase. Grounded in direct code reads (file:line), not estimates, except where explicitly marked "unmeasured" (this environment has no live provider credentials or production telemetry). "Estimated operation cost" uses the `MODEL_PRICING` table (`src/lib/ai/pricing.ts`) against each call's own configured token budget ceiling, not a live average -- a ceiling, not a typical.

## LEGEND

- **Primary/Fallback model**: LUNA = `gpt-5.6-luna`, TERRA = `gpt-5.6-terra`, SONNET = `claude-sonnet-5` (Anthropic).
- **Blocking?**: does the learner-visible response wait on this call.
- **Status**: `UNCHANGED` / `MIGRATED` (this phase moved it onto central routing) / `EXCEPTION` (documented reason it stays off central routing) / `DEAD` (no live caller found).

## CALL GRAPH BY JOURNEY

### PRACTICE
Luna-first, per-unit (batch/chunk/slot) gate, one bounded Terra retry only when a unit is EMPTY (or SHORT for quick_check's all-or-nothing slots). No surplus candidate generation -- `count` requested equals `count` needed. Already optimal; RET-R2/R3-style surplus sizing was deliberately NOT extended here since ordinary single-slot retry already handles the failure mode Practice needs to tolerate.

### RETENTION
8 candidates requested for 6 published (RET-R2 surplus), gate-then-per-question-dedupe (RET-R3), ≤3 AI calls total. Certified in prior phases; unchanged this phase.

### TRANSFER
Generation: bounded regenerate-on-reject loop, ≤2 AI calls, deterministic novelty guard (not AI) decides whether to reject a candidate. Evaluation: single direct-to-Terra call, no Luna attempt, by explicit routing-table design (`rationale: 'evaluation of a learner attempt in a new context'`). No surplus-candidate pattern -- correctly scoped to Transfer's lower request volume relative to question generation.

### GRADING
Deterministic (multiple_choice/matching/ordering/classification): 0 AI calls, unchanged, already correct. Free-text: 1 Terra call, UNLESS the question is `numeric_problem` AND the student's answer is a bare number matching the correct answer within tolerance, in which case **0 AI calls** (new this phase). Explain & Defend's rubric evaluation and conditional misconception classification remain direct-to-Terra, audited and left in place (HIGH_RISK feeds mastery directly; no evidence Luna matches Terra's evaluation accuracy here).

### TUTOR
Was: Anthropic Sonnet, hardcoded, no budget, no telemetry, no fallback (bypassing `CAPABILITY_ROUTING.TUTOR`'s own already-declared "Luna first" intent entirely). Now: Luna-first via central routing, one bounded Terra fallback on outright failure (mirroring the same shape used everywhere else in the canonical runtime), RAG context bounded via `fitContextChunks`, a dedicated `tutor_reply` token budget, full `parseUsage`/`recordRuntimeEvent`/`operationId` telemetry -- all newly added, all previously absent.

### OTHER
Concept explanation, interactive formula, guided practice, error guidance, hint: all already Luna-first, already budgeted, already routed correctly (prior phases). Content-ingestion classification/extraction and cross-cutting localization: migrated this phase from a hardcoded Sonnet path onto the same central routing. Vision transcription stays on Sonnet (documented exception -- no OpenAI vision support in the adapter today). Two legacy call sites (`ai.service.ts`'s `extractConceptsFromText` and `generateQuestion`) and one cognitive-graph inference function are confirmed dead code (no live caller) -- flagged for a future deletion pass, not touched here.

## MODEL ROUTING SUMMARY

| Capability | Primary | Fallback | Rationale |
|---|---|---|---|
| QUESTION_GENERATION | LUNA | TERRA | high-volume structured generation |
| CONTENT_GENERATION | LUNA | TERRA | explanation / worked example / guided practice / localization |
| EXPLANATION_EVALUATION | TERRA | TERRA | semantic verification gates learner-facing content |
| GRADING | TERRA | TERRA | answer-correctness consequence |
| TRANSFER_EVALUATION | TERRA | TERRA | evaluation of a learner attempt in a new context |
| COGNITIVE_ANALYSIS | TERRA | TERRA | feeds cognitive/misconception state |
| CLASSIFICATION | LUNA | TERRA | structured labelling |
| TUTOR | LUNA | TERRA | conversational; Luna first (**now actually wired -- was dead configuration before this phase**) |
| EMBEDDING | `text-embedding-3-small` | same | unchanged |

Every Terra-only (primary=fallback=TERRA) capability carries a non-empty, specific rationale string in `CAPABILITY_ROUTING` itself -- verified by test (`LX-9 required test 10`). No capability was moved off Terra this phase without evidence; GRADING/EXPLANATION_EVALUATION/TRANSFER_EVALUATION/COGNITIVE_ANALYSIS remain Terra-only because their existing rationale (answer-correctness/quality-gate consequence) is sound and no live telemetry exists yet to prove Luna would match Terra's accuracy on these specific evaluation tasks.

## WASTED-CALL / DASHBOARD READ CONTRACT

`src/lib/ai/performance-dashboard-contract.ts` (new this phase) formalizes the B33 data contract: `summarizeByCapability` (calls/latency/tokens/cost/fallback/first-pass-acceptance per capability) and `groupByOperation` + `detectWastedOperations` (correlates a Luna attempt with its Terra fallback via `operationId`, flags the anomaly of a fallback firing after the primary already succeeded). Pure functions over the existing `AIRuntimeEvent` shape -- no new telemetry source, no UI, no DB layer, per B33's own explicit allowance to defer those.
